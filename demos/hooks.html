Phase 2 — 오류 재현

Hook은 루트만 소유한다

이 페이지는 정상 사용 예제가 아닙니다. resc/phase2.md의 “Hook은 최상위 컴포넌트에서만 사용할 수 있습니다” 제약을 일부러 어긴 호출을 실행해, 현재 엔진이 어디까지 막는지 실제 결과로 확인합니다. 두 비교 컨테이너는 서로 격리되어 있어 한쪽의 실패가 다른 쪽 실행을 막지 않습니다.

A. h(Child, props)

엔진이 거부하는 경계 (수정 완료된 방어)

루트가 useState('root')를 먼저 소비한 뒤 h(Child)로 자식 실행 경계에 들어갑니다. 자식 본문의 Hook 호출은 requireHookOwner에서 거부되어야 합니다. 기대: 세 Hook 모두 오류, 자식 본문 다음 문장 미실행, 자식 DOM 없음.

B. Child(props) 직접 호출

엔진이 감지하지 못하는 금지된 사용

아래 컴포넌트는 h()를 거치지 않고 Child(props)로 직접 호출됩니다. 이 경로는 자동 감지 대상이 아니므로, 자식 본문의 useState 두 개가 루트 FunctionComponent의 슬롯을 소비합니다. 요구사항 위반 호출이며 정상 패턴이 아닙니다. 같은 종류(state)와 개수(5개)를 유지한 채 호출 순서만 바꾸면, 슬롯 값이 다른 소유자의 라벨 아래에 나타나는 것을 관찰할 수 있습니다.

  • 기대: Child 값은 CHILD-초기, Child count는 0, Root A는 ROOT-A, Root B는 ROOT-B로 서로 섞이지 않아야 합니다.
  • 실제: 위 컨테이너의 “Child가 읽은 값/Root가 읽은 A” 카드가 현재 렌더의 값을 그대로 보여줍니다. 순서를 바꾼 뒤 값이 서로 옮겨가면 소유자 구분 없이 호출 순서만으로 슬롯을 재사용한 것입니다.
  • 엔진 반응: 이 경로에서는 “Hook 개수·종류” 검사를 통과하므로 오류가 발생하지 않습니다. 이것이 HOOK-10이 막는 h(Child) 경계와 다른 지점입니다.

읽는 방법

  • A의 결과는 각 시도마다 오류 메시지, entered, after, calculate, effect 횟수, 자식 컨테이너 요소 수를 함께 보여줍니다.
  • 상단의 버튼은 정상 앱이 아니라 위반 호출의 상태를 바꾸는 조작입니다. 화면이 초기 상태로 돌아가야 하면 아래 새로고침 버튼을 누릅니다.
