# Phase 2 자식 실행 경계 변경 계획

## 상태와 근거

- **사용자 승인 변경계약**이다. 새 설계 제안이나 도겸 원안 채택이 아니다.
- 순서: 이 계획 작성 → 관련 문서 동기화 → 명세 기반 테스트 작성·변경 전 실행 → 최소 구현 → 같은 테스트·전체 회귀·타입 검사 → 실행 기록 동기화.
- **구현·검증 완료, 독립 검토 2건의 지적 보완 반영.** 명세 검토자의 최종 재검토에서 최초 지적 4건 해결·새 핵심 회귀 없음으로 확인됐다. 사용자 브라우저 실화면 검증은 수행하지 않았다.
- 최종 `npm run check`: 타입 검사 통과, 26개 파일 **293개 실행 통과**. 현재 명세 41개와 Phase 2 실행 100개는 서로 다른 집계다. 이전 전체 270개·Phase 2 77개는 변경 전 기준선이다.
- 요구사항: [Phase 1](../resc/phase1.md), [Phase 2](../resc/phase2.md). 현재 계약: [테스트 명세](p2_test_cases.md), [함수 흐름](p2_function_flow.md), [결정](p2_decisions.md#p2-child-01--자식-즉시-실행과-hook-소유자-차단), [진행표](p2_test_boards.md), [승인안](../wiki/Phase2-Design-merged.md).

## 방향성에서 작업 범위로

- **사용자 방향:** 루트만 Hook을 소유하고 자식은 props만 사용하는 순수 함수라는 제약을 실제 호출 경계에서 지킨다.
- **판단 축:** 자식 Hook 오용을 막되 별도 컴포넌트 트리·식별 체계를 만들지 않는다.
- **따라오는 범위:** `h(Child, props)` 안에서 즉시 실행하며 실행과 반환 정규화 동안 Hook 소유자를 비운다. 기존 요소 VNode와 반환 정규화를 재사용한다.
- **검증 증거:** 자식 본문 진입 후 세 Hook 거부, 정상·중첩·오류 뒤 문맥 복원, 부모 슬롯 비오염과 갱신 재사용, 실패 갱신의 DOM 불변을 함께 확인한다. 예외 발생만으로 통과시키지 않는다.

## 승인된 최소 계약

1. 문자열 첫 인자의 `h`는 기존 요소 `VNode` 반환·props 분류·children 정책을 그대로 유지한다.
2. 함수 첫 인자의 `h`는 자식을 즉시 한 번 실행하고 기존 `normalizeComponentResult`로 `VNode[]`를 반환한다. 지연 실행하지 않는다.
3. 함수 분기는 전달한 props 객체와 내부 객체·콜백 참조를 그대로 전달한다. 속성·이벤트 분류를 하지 않는다. 생략·`undefined`·`null`은 `{}`로 전달하되 필수 props 타입 검증을 느슨하게 만들지 않는다.
4. 함수 분기의 세 번째 이후 인자는 자식 실행 **전에** 거부한다. `props.children` 자동 병합은 지원하지 않는다. 명시한 props의 `children`은 일반 props로 그대로 전달한다.
5. 자식 실행과 반환 정규화 전체에서 `activeHookOwner = null`; `finally`로 직전 소유자를 복원한다. 중첩 자식의 직전 소유자가 null이면 null로 돌아온다. 부모 cursor·phase·슬롯은 초기화하지 않는다. 자식에 `beginHooks`·`endHooks`를 사용하지 않는다.
6. 반환은 기존 규칙 그대로 VNode·중첩 배열·`null`·`undefined`·boolean·빈 배열을 허용한다. 원시 문자열(빈 문자열 포함)·숫자·일반 객체·함수·DOM·Promise는 배열 안에서도 오류다.
7. `ComponentVNode`, resolve 단계, 자식 인스턴스, 자식 key 식별 체계를 만들지 않는다. 요소 key의 Phase 1 계약은 유지한다.
8. `Child(props)` 직접 호출의 자동 감지는 지원하지 않는다. Hook 차단을 보장하는 경계는 `h(Child, props)`다.
9. 콜백 props 실행 자체를 금지하지 않는다. 부모 setter를 자식 버튼 이벤트에 연결하는 사용은 허용한다. 렌더 도중 setter 정책·예약 방식·실패 복원 정책은 변경하지 않는다.

## 문서·구현 경계

- 실제 구현은 `src/component/index.ts`의 공개 `h` 오버로드와 내부 `renderChild` 1개다. `src/component/h.ts`의 기존 요소 `h`를 `createElementVNode` 별칭으로 가져오고 `normalizeComponentResult`를 재사용했다. 기존 h.ts는 변경하지 않았다.
- 공개 함수 타입은 제네릭 오버로드로 필수 props를 검사한다. 내부의 `(props: never) => unknown`과 `as never`는 서로 다른 props 타입의 함수 호출 처리를 내부로 한정한 선택이며 공개 타입을 느슨하게 만드는 계약이 아니다. 기존 `requireHookOwner`의 오류 문구도 그대로다.
- 동기화 대상은 이 계획, p2 테스트 명세·흐름·결정·진행표, 병합 승인안뿐이다. 도겸 원본과 Phase 1 수정 제한 문서 4개는 수정하지 않는다.
- 문서 담당자는 코드·테스트·`skills-lock.json`을 수정하거나 커밋·푸시하지 않는다.

### 검토 지적 보완과 최종 실행

- 독립 검토 2건은 제품 실행 로직 오류를 찾지 않았고 명세 대비 검증 누락을 지적했다. 소스 재설계 없이 테스트를 보완했다. 이후 명세 검토자 최종 재검토에서 최초 지적 4건 모두 해결·새 핵심 회귀 없음으로 확인됐다.
- HOOK-10–13의 바깥 세 Hook 거부를 최초 표시·각 갱신 직후에 검사한다. HOOK-12 세 fixture의 갱신 후 로그·진입·다음 문장·setter를 보강했다. HOOK-13의 memo 오용 및 getter memo 입력은 `A/B → A2/B → A2/B2` 각각의 시점과 진입/catch 1→2→3회를 검사한다. ERR-03도 실패/정상 콜백 직후 각각 바깥 Hook 거부를 확인한다.
- H-09 여분 인자 3건은 명세 원본과 동일한 Child·props로 맞추고 진입 0회를 확인했다.
- 타입 검사는 최종 `tests/unit/p2/h.types.ts`의 실행하지 않는 `assertHTypeContract()`다. `tsconfig.json`이 tests를 포함하고 Vitest는 `tests/**/*.test.ts`만 실행하므로 이 파일의 런타임 실행은 0이다. 필수 props·undefined/null·타입 불일치·여분 인자는 `@ts-expect-error`, 반환 타입 VNode/VNode[]는 대입으로 확인한다.
- 중간 `h.types.test.ts`의 함수 존재만 확인하는 자명한 테스트는 검토 후 제거했다. 당시 27개 파일 294개·Phase 2 101개는 **중간 수치**이며 최종 집계에 포함하지 않는다.
- 보완 후 `npx vitest run tests/unit/p2/h.test.ts tests/unit/p2/hooks.test.ts tests/integration/p2/errors.test.ts`: 3개 파일 84개 통과. `npm run typecheck` 통과. `npx tsc --noEmit --listFiles` 출력으로 h.types.ts 포함도 확인했다.
- 주 담당자 최종 `npm run check` 재실행 및 이번 문서 담당자의 재실행: 타입 검사 통과, **26개 파일 293개 통과**, 오류 누락 없음. Phase 2는 **26+50+16+8=100개**, 기준선 77 대비 +23. Phase 1은 **193개**로 동일하다. 명세 ID·진행표는 **41개** 그대로다.
- 주 담당자 `npm run build`: `tsc --noEmit`과 `vite build` 성공. 사용자 브라우저에서 실제 화면을 검증한 결과는 아니다.
- 문서 담당자 추가 확인: `npx vitest run tests/unit/p2 tests/integration/p2 --reporter=verbose`에서 4개 파일 100개 통과. 앞선 JSON 보고서 파이프의 JSON 파싱 실패는 집계 도구 실패였으며 제품 테스트 실패로 기록하지 않는다. 명세 ID·진행표 41행 O 일치, 문서 6개 로컬 파일/제목 링크 59개와 문서 차이 형식 검사도 확인했다.

### 검증 한계

직접 `Child(props)` 자동 감지·SVG·Hook 정적 분석·갱신 횟수는 기존 범위 밖이다. 정규화 중 Hook 차단은 배열 인덱스 getter로 확인했으며 Proxy·특수 반복자 전반을 검증했다고 주장하지 않는다. 렌더 도중 setter 정책도 이번에 변경하거나 새로 검증한 것이 아니다. DOM 증거는 자동 테스트의 jsdom 관찰이며 사용자 브라우저 실화면 검증은 수행하지 않았다.
