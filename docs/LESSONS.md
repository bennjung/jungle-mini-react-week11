# 작업 교훈

## 내부 타입은 생산자와 소비자의 실제 계약부터 확인한다

- **사례:** `AttributeUpdate`에서 변경이 없는 속성 목록도 빈 배열로 반환하도록 정해, `collectNodeChanges()`가 빈 배열을 다시 걸러내는 코드가 생겼다.
- **교훈:** 내부 반환 타입을 정하기 전에 생산자가 어떤 결과를 만들고 소비자가 어떤 형태를 실제로 필요로 하는지 함께 확인한다. 변경 없음이 유효한 결과라면 빈 배열을 강제하는 대신 필드 생략이 더 단순할 수 있다.
- **주의:** 모든 필드를 선택 항목으로 바꾸지는 않는다. `ChildMatch`처럼 분류에 따라 반드시 필요한 값은 필수로 유지해 잘못된 상태를 방지한다. 공유 타입은 내부 타입과 영향 범위를 구분한다.
- **검증:** 변경이 전혀 없을 때 불필요한 명령이 만들어지지 않는지, 일부 필드만 바뀌었을 때 해당 변경만 전달되는지, 기존 명령과 테스트 계약이 유지되는지 확인한다.
